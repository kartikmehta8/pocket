title: Creating an agent

An agent is whatever you already use to do the work. Pocket gives it a wallet
and a set of limits.

## Create it

Go to **Agents** and choose **New agent**. Give it a name, and optionally a line
about what it does.

A wallet is created at the same time, and the address appears on the agent's
page.

<Callout type="info">
Your new agent cannot spend anything yet. It stays that way until you give it a
budget, which is the next page.

</Callout>

## Fund the wallet

Copy the address from the agent's page and send it some stablecoin. The
**Connect agent** screen links to a faucet if you are on testnet.

The wallet is already set up to hold the token, so there is nothing else to do.
The balance appears once the transfer confirms.

## Connect the agent you run

Open **Connect agent** in the dashboard and copy the line for whichever agent
you use.

<Tabs items={['Hermes', 'Claude Code', 'Other agents']}>
<Tab value="Hermes">

```bash
hermes mcp add pocket --transport http --url https://your-mcp-url/mcp \
  --header "Authorization: Bearer pocket_sk_..."
```

</Tab>

<Tab value="Claude Code">

```bash
claude mcp add --transport http pocket https://your-mcp-url/mcp \
  --header "Authorization: Bearer pocket_sk_..."
```

</Tab>

<Tab value="Other agents">

Any MCP client takes the same endpoint and the same header:

```json
{
  "mcpServers": {
    "pocket": {
      "type": "http",
      "url": "https://your-mcp-url/mcp",
      "headers": { "Authorization": "Bearer pocket_sk_..." }
    }
  }
}
```

</Tab>

</Tabs>

The key is the one you minted in the dashboard. Mint a separate key per runtime
so you can revoke one without disturbing the others.

## The model never holds the key

<Flow
  caption="The key sits in your runtime's config; the model only ever asks for a purchase"
  nodes={[
    { label: 'Language model', note: 'no credential at all' },
    { label: 'Your agent', note: 'asks to buy' },
    { label: 'Your runtime', note: 'sends the key', decides: true },
    { label: 'Pocket', note: 'checks and pays' },
  ]}
/>

The key lives in your runtime's configuration and travels as a transport
header. It is never passed to the model, never returned in a tool result, and
never written into the context. A model that cannot read it cannot leak it.

Pocket's MCP server stores no key of its own, so the endpoint reaches only the
organization whose key the caller already holds.

## What it can do once connected

Eight tools reach your agent. One can spend, and the other seven exist so it
does not have to guess.

| Tool                        | What it does                             | Spends |
| --------------------------- | ---------------------------------------- | ------ |
| `pocket_pay_for_resource`   | Buys something and returns the content   | Yes    |
| `pocket_preview_payment`    | Asks whether a purchase would be allowed | No     |
| `pocket_create_task_budget` | Opens a ring-fenced amount for one job   | No     |
| `pocket_list_agents`        | Lists agents with budgets and spend      | No     |
| `pocket_get_agent`          | One agent, with its limits and balance   | No     |
| `pocket_spend_summary`      | Spend by category and seller             | No     |
| `pocket_list_payments`      | Recent purchases, refusals included      | No     |
| `pocket_audit_trail`        | The full record                          | No     |

## Pausing and revoking

On the agent's page you can **pause** it, which refuses everything until you
resume, or **revoke** it, which is permanent. A revoked agent keeps its history
and can never spend again.

## Deleting an agent

**Delete agent**, on the agent's page, retires it for good. It stops being
offered anywhere and can never spend again.

What it does not do is erase what the agent spent. Its payments stay on
**Payments** and **Audit** under the name it had, refusals included. Deleting an
agent hides the agent, never the record.

If the wallet still holds money, Pocket will not let you delete until it has
somewhere to go. The dialog asks which of your other agents should have it,
moves the whole balance in one transaction, and then retires the agent. There
is no way to strand funds behind a page you can no longer open.

## Getting good behaviour

Three things make an agent predictable:

- **Name the agent in your prompt.** Otherwise it guesses, and it may guess wrong.
- **State a ceiling.** It cannot exceed its real limits either way, but a stated number gives it something to plan against.
- **Say what to do when refused.** "Tell me what you can afford instead" turns a dead end into a useful answer.

The **Capabilities** screen has prompts already filled in with your own agent's
details, ready to copy.
