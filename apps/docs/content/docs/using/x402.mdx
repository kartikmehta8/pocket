---
title: Buying with x402
description: How your agent pays for things, and why it can buy from anyone rather than a catalogue we curate.
---

x402 is an open way for a web service to say "this costs money" and be paid for
it in the same request. Your agent asks for something, the seller answers with a
price instead of the data, your agent pays, and the data comes back.

Pocket handles all of it. You do not need to understand the protocol to use it.

## Why it matters to you

**You are not locked into a marketplace.** Pocket does not run a catalogue and
there is nothing to get listed in. Any API priced this way can take your agent's
money, whether we have heard of it or not.

**It is per call, not per seat.** Your agent pays for the work it actually does,
rather than a monthly licence sitting idle between jobs.

**No account setup with each seller.** No signup, no API key to rotate, no
invoice to reconcile. The payment is the request.

## Trying it from the dashboard

Open **Marketplace**. It lists paid feeds with live prices and how fresh each
one is. Pick which agent pays, press buy, and the response appears inline.

Every card names its **paid endpoint**. That address is the thing an agent is
eventually pointed at, and a marketplace that hid it would teach you nothing
about the protocol underneath. Copy it and hand it to an agent, or paste it into
the box for any other paid URL and buy from a seller that is not on the list at
all.

A purchase you make here goes through exactly the same limits an agent's does.
The only difference recorded is that a person asked.

| Feed                     | Price | Refreshes | Data from                       |
| ------------------------ | ----- | --------- | ------------------------------- |
| Spot prices              | 0.01  | 60s       | CoinGecko                       |
| Ethereum fee conditions  | 0.02  | 20s       | A public Ethereum node          |
| Chain TVL leaderboard    | 0.05  | 10m       | DefiLlama                       |
| Stablecoin supply        | 0.08  | 15m       | DefiLlama                       |
| Ethereum market brief    | 0.08  | 5m        | All three, joined               |
| Full ecosystem deep dive | 0.75  | 5m        | The brief, plus the full tables |

These are live feeds, not sample responses.

<Callout type="info">
If the paying wallet cannot cover the price, the buy button is disabled and says
so. That is arithmetic rather than a policy decision: nothing is signed and
nothing is recorded, so an empty wallet does not fill your payments list with
refusals. Top it up from [the faucets](/docs/using/funding).

</Callout>

## Letting your agent do it

Once connected, your agent buys on its own. Give it a job that needs paid data:

```text
Using my agent "Atlas Research", get current token prices from
https://seller.example.com/v1/market/prices and tell me which asset moved
most in the last 24 hours.
```

Name the agent, and give it the URL. The **Capabilities** screen has prompts
with both already filled in from your own account.

Behind the scenes it calls one tool, `pocket_pay_for_resource`, and Pocket does
the rest.

## Buying from your own code

If you are calling Pocket directly rather than through an agent, one request does
the whole thing:

```bash
POST /v1/payments/x402/purchase
Authorization: Bearer pocket_sk_...

{
  "agentId": "agent_1a2b3c",
  "url": "https://seller.example.com/v1/data",
  "reason": "Prices for the portfolio view"
}
```

It answers with one of four outcomes, and a refusal is a normal `200` rather
than an error:

| Outcome   | Means                           | Also returns                 |
| --------- | ------------------------------- | ---------------------------- |
| `paid`    | Bought and delivered            | The data and the receipt     |
| `free`    | The seller charged nothing      | The data                     |
| `blocked` | Refused or held. Nothing signed | The reason and what was left |
| `failed`  | Reachable but did not complete  | A message and a code         |

Amounts are always decimal strings beside their asset, never numbers. A JSON
number gets turned back into a float by every client, and a ledger cannot afford
that.

```json
{ "amount": "0.08", "asset": "USDC" }
```

## When a seller refuses

A seller answers a rejected payment exactly as it answers an unpaid request:
`402`, an empty body, and the reason in a header. Pocket reads the header, so
what reaches you is the seller's own words rather than an empty object.

```text
The seller refused the payment (402): No matching payment requirements.
This usually means the wallet is empty, the price changed between the
quote and the payment, or the seller does not accept this asset.
```

The usual cause is the first one. Check the wallet balance on the agent's page
before looking any further.

## Where the money actually goes

Settlement happens on Hedera, and the network fee is paid for your agent rather
than by it. See [Hedera](/docs/stack/hedera).
